Design decisions

1
Filter bar, not sidebar expansionThe sidebar is used for jump navigation. Mixing filter controls there conflates two mental models. Inline bar keeps filters visible alongside results at all times.
2
Multi-select chips per dimensionMost common ops task: "show me all stalled Developers on opus". That needs AND-across-dimensions + OR-within-dimension. Chips make the active state visible without a dropdown.
3
Sidebar dims, doesn't filterSidebar stays complete as a "table of contents" — filtered-out workers are dimmed. This preserves spatial navigation even when viewing a filtered subset.
4
"X of Y workers" counterThe counter in the filter bar tells the user at a glance how many workers the current filter returns, removing ambiguity about whether the empty grid is a data problem or a filter issue.
5
Stats row stays globalThe stats (Working / Queued / Completed) reflect the full fleet, not the filtered view. A future iteration could add a toggle, but global context is safer as default.
