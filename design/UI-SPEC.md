# Full UI Redesign — Design Contract

> Visual and interaction contract for a complete redesign of the vibe-kanban local web app.
> Generated by gsd-ui-researcher (non-interactive run). Verified by gsd-ui-checker.
> This document is the new source of truth. On any conflict with
> `design/DESIGN-DIRECTION.md`, `packages/local-web/AGENTS.md`, or code in the
> repo, **this document wins** — those describe two earlier, now-abandoned
> attempts that never fully landed (see "Why this redesign" below).

---

## Why this redesign

Investigation of the current codebase found **three overlapping, unreconciled
design languages**, which is the concrete cause of the "quedó inconsistente"
feeling reported by the user:

1. `packages/local-web/AGENTS.md` still documents a "Clean Modern Professional"
   direction — Plus Jakarta Sans + IBM Plex Mono, `rounded-xl` = 14px,
   `rounded-2xl` = 16px, lucide-react icons, soft-shadow elevation.
2. `design/DESIGN-DIRECTION.md` ("ProjectFlow") layered a Material Design 3
   direction on top — Hanken Grotesk + Geist, blue primary `#004ac6`,
   **small radii** (`rounded-xl` = 8px), Material Symbols icons, colour-based
   elevation. This is what `packages/web-core/src/app/styles/new/index.css`
   and `packages/local-web/tailwind.new.config.js` actually implement today.
3. Component code in `packages/ui/src/components/*` (e.g. `Card.tsx` using
   `rounded-xl bg-primary ... shadow-card`) was written against direction (1)
   and was **never updated** when the tokens moved to direction (2) — so
   `rounded-xl` in markup now silently resolves to 8px instead of the 14px the
   component was designed for.
4. Icon usage is split three ways: 139 files import `@phosphor-icons/react`
   (legacy, AGENTS.md says "do not add new"), 51 files import `lucide-react`,
   and only 2 files use the mandated `material-symbols` set.

This UI-SPEC replaces all three directions with a single new one, chosen fresh
per user instruction (do not carry over the MD3 blue palette or Hanken
Grotesk/Geist pairing by default).

## Palette: "Slate & Signal"

Rationale (sober but trendy, professional, differentiated from the deprecated
MD3 blue): near-neutral **zinc/slate** surfaces (not tinted blue — this is the
explicit lesson from the 20-jul PM feedback baked into the deprecated doc, and
it still applies) with a single **indigo** accent hue reserved strictly for
interactive/active elements. Indigo-on-neutral-zinc is the palette family
behind most of today's well-regarded professional dev-tool UIs (Linear,
Vercel, Raycast) — it reads modern and a little more distinctive than generic
blue, while staying restrained (one accent hue, no gradients, no multi-color
branding).

All values are HSL triplets (Tailwind/shadcn convention already used in the
codebase) with the hex noted for reference. These replace every `--md-*`
token in `index.css`; `--md-*` variable names may be kept as internal aliases
during migration but must resolve to these values, not the current MD3 blue
ones.

**60/30/10 distribution:** `background` (60%, dominant) is the app canvas
behind every view. The **30% mid-tier is the `surface-container-*` scale as a
group** — `surface-container-lowest` through `surface-container-high` —
which covers every card, top bar, dialog, input, dropdown, and hover state;
these are the surfaces a user actually looks at most of the time (cards on
top of background), so together they're the second-largest area even though
individually each shade is a small increment. `brand`/`brand-on-surface` is
the remaining 10%, accent-only per the reserved-for list below.

**Accent reserved for** (explicit list — nothing else may use `brand`/`brand-on-surface`):
- Primary CTA buttons (solid fill)
- Active/selected nav item (Workers · Sprint · Issues tabs, active mobile tab)
- Active filter tabs / segmented control selection
- Focus rings (`focus-visible:ring-2 focus-visible:ring-brand-on-surface`)
- Links and "view" affordances inside body text
- Selected checkbox/radio fill and checked task-card accent bar
- Loading/progress indicators tied to an active worker/task

Everything else (cards, sidebars, top bar, inputs, dialogs, empty states,
default badges) stays on the neutral zinc scale. This directly enforces the
20-jul lesson learned: **surfaces stay near-neutral; strong color is only for
accents, active states, focus.**

| Token | Light | Dark | Usage |

foreground; text-only usage (e.g. a colored status label with no fill) uses
the theme-appropriate value from the table above.

## Typography

Two families, both self-hosted via npm (no CDN) — no change to the
"bundle via npm" constraint, only to which font:

- **Geist** (UI: headings, body, labels) — `@fontsource/geist`, already
  a dependency, weights **400 and 600 only**. Fixes a live bug:
  `tailwind.new.config.js` currently maps `fontFamily.geist` to `'monospace'`
  as fallback — Geist is a **sans** family, this must be corrected as part of
  the redesign.
- **Geist Mono** (branch names, commit hashes, IDs, code, terminal output) —
  new dependency `@fontsource/geist-mono`, weight **400 only**. Replaces the
  current mismatched setup where the `ibm-plex-mono` Tailwind alias actually
  resolves to `Geist` (sans) instead of a real mono face.

Drop: Hanken Grotesk, Plus Jakarta Sans, IBM Plex Mono (font files), Material
Symbols font (icon set retired — see Iconography).

**4 sizes, 2 weights — no exceptions.** This app is a dense dev tool, not a
marketing surface, so page-level "Display" text is dropped as a distinct
role; `Heading` covers page/section/dialog titles at every scale that
previously would have used Display. Emphasis within a role is carried by
color (`brand-on-surface` for active states) and letter-spacing (uppercase
tracking for Label), never by a third weight.

| Role | Size | Weight | Line height | Notes |
|------|------|--------|-------------|-------|
| Heading | 20px (1.25rem) | 600 | 1.3 (26px) | Page titles, section titles, dialog titles, column headers |
| Title | 16px (1rem) | 600 | 1.4 (22px) | Card/row titles, issue titles |
| Body | 14px (0.875rem) | 400 | 1.5 (21px) | Default body copy, form labels, buttons |
| Label | 12px (0.75rem) | 400 | 1.4 (17px) | Metadata, badges, timestamps, uppercase eyebrow labels (`tracking-wide uppercase` — emphasis via tracking/color, not a heavier weight) |

Two weights, system-wide, no role-specific exceptions: **400 (regular)** for
Body and Label, **600 (semibold)** for Heading and Title (and anywhere else
that needs to stand out, e.g. active nav labels).

Monospace (Geist Mono, 400) at 12px/16px for branch names, hashes, worker IDs,
diff/log content — unchanged pattern from today, just the correct font.

## Spacing Scale

8-point scale, multiples of 4 only (no exceptions carried over from the old
`half` 2px / `plusfifty` 6px tokens — those break the rule and must be
retired):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gaps, tight inline padding |
| sm | 8px | Compact element spacing, row gaps |
| md | 16px | Default element spacing, card padding, gutter |
| lg | 24px | Section padding, page container padding |
| xl | 32px | Layout gaps between major regions |
| 2xl | 48px | Major section breaks |
| 3xl | 64px | Page-level spacing (empty states, onboarding) |

Exceptions:
- Icon-only touch targets: 44×44px minimum on mobile tab bar / mobile nav
  buttons (accessibility, not a spacing token — applies to hit area, not
  visual size).
- Nav rail / primary-content-panel width: keep existing `sidebar` token
  (240px) for any left-hand list panel (e.g. workspace list) — it's a fixed
  layout dimension, not part of the spacing rhythm.

## Shape & Elevation

- **Radii** — single small-to-medium scale, replacing both the old 14/16px
  AGENTS.md scale and the current 2/4/8px MD3 scale (neither is followed
  correctly today):
  - `sm` 6px — chips, small controls, checkboxes
  - `md` 8px — buttons, inputs, dropdown items (component code default)
  - `lg` 10px — cards, list rows, dialogs, popovers
  - `xl` 14px — feature cards (Worker cards), bento/stat cards
  - `full` 9999px — badges, pills, avatars, status dots
- **Elevation** — soft, diffused shadows (not MD3 color-elevation, not hard
  borders):
  - `shadow-soft` — resting state hint (1px)
  - `shadow-card` — resting card
  - `shadow-card-hover` — hover, paired with `hover:-translate-y-0.5`
  - `shadow-elevated` — sticky top bar, panels
  - `shadow-overlay` — dialogs, popovers, dropdowns, tooltips
  - `shadow-focus` — programmatic focus glow (pairs with `ring-brand-on-surface`)
- **Borders** — `border-outline-variant` (1px) default everywhere; never
  pure black; dashed variant (`border-dashed border-outline-variant`) for
  empty-state drop zones only.
- **Micro-interactions**: `active:scale-[0.98]` on buttons, 150ms transitions
  on color/shadow, `hover:-translate-y-0.5` on cards only (not on buttons,
  rows, or nav items — keep lift restricted to card-shaped surfaces so it
  doesn't feel busy across a dense list view).

## Iconography

**lucide-react is the single icon set going forward.** It already covers 51
files (the largest non-legacy footprint), matches the "modern professional
SaaS" reference points behind the palette choice (Linear/Vercel/Raycast all
use a Lucide-class icon system), and needs zero new dependency.

- Retire Material Symbols entirely (2 files, `packages/ui/src/components/MaterialIcon.tsx`
  usage in `Navbar.tsx`/`NavbarContainer.tsx`) — replace with lucide
  equivalents (`Sun`/`Moon`/`Monitor` for theme cycle, `ChevronLeft` for back,
  `Menu` for drawer, etc.) as those specific views are touched.
- Retire `@phosphor-icons/react` (139 files, legacy) — do not add new phosphor
  icons anywhere, including chat/editor components (this loosens the current
  AGENTS.md carve-out; full migration is incremental, tracked outside this
  spec, but every net-new or redesigned component uses lucide only).
- Stroke width: `1.75` default, `2` for emphasis, `2.5` for 12px icons
  (unchanged from current AGENTS.md guidance — this detail was correct).
- Sizes: `14px` (small buttons), `16px` (default), `20px` (large/section
  headers), `28px` (empty-state medallions).
- Active/selected icon state = `brand-on-surface` color, not a filled icon
  variant (lucide icons don't have a MD3-style FILL axis — use color + weight
  400→2 stroke to signal active instead).
- **Icon-only button accessibility contract (mandatory, no exceptions):**
  every icon-only control (`Button` `icon` variant, `NavbarIconButton`,
  mobile tab bar items, dropdown trigger icons, card row action icons) must
  carry both an `aria-label` describing the action (not the icon name) and a
  visible-on-hover `title`/`Tooltip` with the same or a shortcut-augmented
  string — this is already the pattern `NavbarIconButton` uses via `Tooltip`
  + `aria-label={item.tooltip}`; extend it to every icon-only control touched
  in the redesign, no icon ships without one.

## Visual Hierarchy

The primary focal point of the main screen (Sprint / Kanban board) is the
**active worker's in-progress task card** — the card tied to a currently
running agent. It is the only place `brand`/`brand-on-surface` accent may
appear as a persistent (non-hover, non-focus) treatment: a subtle `brand/10`
left accent bar plus a live pulsing status dot, layered on the same neutral
card surface as every other card (never a tinted card background). Every
other element on the board — columns, other cards, the top bar — recedes to
the neutral zinc scale so this one state reads as "the thing happening right
now" at a glance, which is the core job of this screen.

extend it to any redesigned destructive flow that doesn't yet have it (e.g.
issue deletion body copy, if missing).
